# /feature Command

> Manage feature folders through the 4-state workflow

---

## Usage

```bash
/feature                    # List features by state
/feature <name>             # View specific feature details
/feature take <name>        # Move from planned/ to active/
/feature pause <name>       # Move from active/ to backlog/
/feature complete <name>    # Move from active/ to completed/
/feature plan <name>        # Move from backlog/ to planned/
```

---

## The 4-State Workflow

```
backlog/ <-> planned/ -> active/ -> completed/
   ^                     |
   +---------------------+ (if paused)
```

| State | Purpose |
|-------|---------|
| `backlog/` | Ideas captured, not prioritized |
| `planned/` | Prioritized, ready to start |
| `active/` | In development (1-2 max) |
| `completed/` | Done and documented |

---

## Feature Folder Structure

Each feature is a **FOLDER** (not a file) with rich content:

```
feature-name/
+-- 00-INDEX.md           # Index of contents
+-- 01-VISION.md          # Vision and objectives
+-- 02-FOUNDATIONS.md     # Technical foundations
+-- 03-*.md ... 08-*.md   # Research, concepts, ideas
+-- 09-DECISIONS.md       # Decisions made
+-- STATUS.md             # Current state (REQUIRED)
+-- [any other files]     # Research, notes, etc.
```

**IMPORTANT**: A folder is only a feature if it contains `STATUS.md`.

---

## STATUS.md Required Fields

Every feature STATUS.md MUST include:

```yaml
# Required
state: backlog|planned|active|completed
depends_on: []
blocks: []

# Required for implementation
required_skills:
  - tdd-guard
  - test-patterns
  - [other relevant skills]

# Verification steps (MANDATORY)
pre_implementation:
  - "Write first test for [specific behavior]"
  - "Run test, verify FAILS"
  - "Implement minimal code"
  - "Run test, verify PASSES"
```

## Implementation

### List Features (`/feature`)

```bash
echo "=== FEATURES ==="

echo "BACKLOG:"
for dir in _workspace/features/backlog/*/; do
    if [[ -f "${dir}STATUS.md" ]]; then
        name=$(basename "$dir")
        count=$(find "$dir" -type f | wc -l)
        echo "  - $name ($count files)"
    fi
done

echo "PLANNED:"
for dir in _workspace/features/planned/*/; do
    if [[ -f "${dir}STATUS.md" ]]; then
        name=$(basename "$dir")
        count=$(find "$dir" -type f | wc -l)
        echo "  - $name ($count files)"
    fi
done

echo "ACTIVE:"
for dir in _workspace/features/active/*/; do
    if [[ -f "${dir}STATUS.md" ]]; then
        name=$(basename "$dir")
        count=$(find "$dir" -type f | wc -l)
        echo "  - $name ($count files)"
    fi
done

echo "COMPLETED:"
for dir in _workspace/features/completed/*/; do
    if [[ -f "${dir}STATUS.md" ]]; then
        name=$(basename "$dir")
        count=$(find "$dir" -type f | wc -l)
        echo "  - $name ($count files)"
    fi
done
```

### View Feature (`/feature <name>`)

1. Find the feature folder in any state
2. Read and display STATUS.md
3. List all files in the folder
4. Show current state (backlog/planned/active/completed)

### Take Feature (`/feature take <name>`) - ENHANCED

**CRITICAL**: This command enforces implementation-guard via persistent context injection.

#### Step 1: Move Feature

1. Verify feature exists in `planned/`
2. Move entire folder to `active/`
3. Update STATUS.md with:
   - `state: active`
   - `started: YYYY-MM-DD`

#### Step 2: Generate ACTIVE_SKILLS.md (MANDATORY - PERSISTENT CONTEXT)

1. Read STATUS.md
2. Extract `required_skills` list
3. FOR EACH SKILL: Read `.claude/skills/<skill>/SKILL.md`
4. CONCATENATE all skill content into `.claude/context/ACTIVE_SKILLS.md`
5. This file is ALWAYS in context via CLAUDE.md reference

**CRITICAL**: The ACTIVE_SKILLS.md file must be written with this format:

```markdown
# ACTIVE SKILLS - AUTO-GENERATED
# Feature: <name>
# Generated: YYYY-MM-DD
# DO NOT EDIT - This file is auto-generated by /feature take

---

## MANDATORY READING - Skills loaded for current feature

[FULL CONTENT of each required skill concatenated here]

---

## ACTIVE FEATURE CONTEXT

Feature: <name>
State: active
Started: YYYY-MM-DD
Required Skills: [list]

REMINDER: Follow TDD cycle - RED -> GREEN -> REFACTOR
```

#### Step 3: Show Pre-Implementation Checklist

Display the verification protocol:

```
================================================================================
                    IMPLEMENTATION GUARD - ACTIVATED
================================================================================

Feature: <name>
Required Skills Loaded:
  ✓ tdd-guard
  ✓ test-patterns
  ✓ [others...]

PRE-IMPLEMENTATION CHECKLIST:
┌─────────────────────────────────────────────────────────────────────────────┐
│ BEFORE writing ANY implementation code:                                     │
│                                                                             │
│ 1. [ ] Identify FIRST behavior to test                                      │
│ 2. [ ] Write ONE test for that behavior                                     │
│ 3. [ ] Run test → Verify it FAILS (show output)                             │
│ 4. [ ] Write MINIMAL code to pass                                           │
│ 5. [ ] Run test → Verify it PASSES (show output)                            │
│ 6. [ ] Repeat for next behavior                                             │
│                                                                             │
│ REMEMBER: Feature docs are SPECS, not code to copy!                         │
└─────────────────────────────────────────────────────────────────────────────┘

TDD CYCLE REMINDER:
  RED (fail) → GREEN (pass) → REFACTOR → repeat

Ready to implement. Follow the cycle above for each behavior.
================================================================================
```

#### Step 4: Update Tracking

1. Update `_workspace/tracking/STATUS.md`:
   - Set `session.active_feature: <name>`
2. Add to `_workspace/tracking/CHANGELOG.md`:
   - Entry: `"Started feature: <name> (skills loaded: X, Y, Z)"`

### Pause Feature (`/feature pause <name>`)

1. Verify feature exists in `active/`
2. Move entire folder to `backlog/`
3. Update STATUS.md with:
   - `state: backlog`
   - `paused: YYYY-MM-DD`
   - `reason: [user provided]`
4. **CLEAR** `.claude/context/ACTIVE_SKILLS.md` (write empty or delete)
5. Clear `session.active_feature` in `_workspace/tracking/STATUS.md`
6. Add to CHANGELOG

### Complete Feature (`/feature complete <name>`)

1. Verify feature exists in `active/`
2. Verify all tests pass (run test suite)
3. Move entire folder to `completed/`
4. Update STATUS.md with:
   - `state: completed`
   - `completed: YYYY-MM-DD`
5. **CLEAR** `.claude/context/ACTIVE_SKILLS.md` (write empty or delete)
6. Clear `session.active_feature` in `_workspace/tracking/STATUS.md`
7. Add to CHANGELOG
8. Suggest: **"Run /checkpoint to commit changes"**

**IMPORTANT**: All files are preserved - nothing is deleted.

### Plan Feature (`/feature plan <name>`)

1. Verify feature exists in `backlog/`
2. Move entire folder to `planned/`
3. Update STATUS.md with:
   - `state: planned`
   - `planned: YYYY-MM-DD`
4. Add to CHANGELOG

## Integration

| System | Interaction |
|--------|-------------|
| `_workspace/features/` | Read/move feature folders |
| `_workspace/tracking/STATUS.md` | Set/clear `session.active_feature` |
| `_workspace/tracking/CHANGELOG.md` | Log feature state changes |
| `.claude/skills/` | Load required skills on /feature take |
| `implementation-guard` | Activated automatically on take |
| `/status` | Shows features in all 4 states |
| `/checkpoint` | Suggested after completing feature |

---

## Notes

- **Max 2 active features** recommended (avoid context switching)
- All content is preserved when moving - nothing is deleted
- STATUS.md is the source of truth for feature state
- Features without STATUS.md are ignored by the system
- **Skills are MANDATORY** - /feature take loads them automatically
